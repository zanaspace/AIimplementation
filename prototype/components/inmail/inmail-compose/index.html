InMail Smart Compose & Summaries

Adds three things to CICOD InMail. Summarise gives a TL;DR of a long thread, and Summarise unread does the same for the inbox. Draft from notes turns bullet points into an official letter or circular in the MDA format, with a tone selector. For circulars it suggests the audience (departments and grade levels) and writes a plain-language summary. A pre-send check catches problems such as Secret content going to an external address.

Screen: InMail → Compose / Inbox / CircularComponent: <ai-mail-assist>Endpoint: /inmail/summarise, /inmail/draft, /inmail/presend-check

2. How it works

A sovereign LLM with MDA letter and circular templates, the staff directory for audiences, and a rules + classifier data-loss check before Send.

Capture

Summaries send the visible messages (sender, date, body). Drafts send the notes, tone and message type. The pre-send check sends recipients, classification, subject, body and attachment count.

Protect

Mail is Restricted by default, so all three calls stay on the sovereign model. NIN and phone numbers are masked before the prompt. Secret threads can be summarised but not sent to any external model.

Draft

The LLM fills the tenant's letter template (Ref, Date, Subject, body, sign-off "For: Permanent Secretary") or the numbered circular template in the chosen tone.

Target

For circulars, topic keywords are matched to the directory: APER goes to every department at GL 07–17, budget notes to Finance, Audit and Planning. The LLM writes a plain-language summary.

Check

Rules and a classifier flag Secret content with non-@cicod.com recipients (this blocks the send), a mentioned but missing attachment, an empty subject, personal numbers and a circular with no audience.

Confirm & learn

Insert, Regenerate, Discard, each Fix and every Send anyway go to /feedback. Overrides are also written to the audit log.

4. How to implement it in InMail

Mount (inbox, thread, compose)

<link rel="stylesheet" href="/ai/components/inmail-compose.css">
<script src="/ai/shared/ai-gateway.js"></script>
<script src="/ai/components/inmail-compose.js"></script>

<ai-mail-assist mode="inbox"  source="#message-list"></ai-mail-assist>
<ai-mail-assist mode="thread" source="#reading-pane"></ai-mail-assist>
<ai-mail-assist mode="compose" form="#compose-form"
                sender="Prince Ekpenyong" mda="CICOD"></ai-mail-assist>

<script>
document.addEventListener('ai-mail-insert', e => compose.fill(e.detail));
document.addEventListener('ai-mail-fix',    e => compose.set(e.detail.field, e.detail.value));
document.addEventListener('ai-mail-send',   e => compose.send({ aiOverride: e.detail.overridden }));
</script>

Build steps

  1. Load the tenant's letter and circular templates (letterhead, Ref format, sign-off) into the gateway's template store.
  2. Expose /inmail/summarise and /inmail/draft on the sovereign LLM.
  3. Expose the directory (departments, grade levels, head counts) to the audience suggester.
  4. Build /inmail/presend-check: domain allow-list, classification rules, attachment and PII detectors.
  5. Route Send through the check. High-severity issues block the send; the others allow Send anyway with an audit entry.

API contract

    "summary": "What this means for you: …" }

POST /ai/inmail/summarise
{ "scope": "thread", "messages": [{ "from": "Zana", "body": "…" }] }
→ { "tldr": "…", "points": ["…"],
    "asks": [{ "who": "Zana", "what": "…", "due": "Friday" }] }

POST /ai/inmail/presend-check
{ "to": ["a.bello@examplemail.com"], "classification": "Secret",
  "subject": "…", "body": "…", "attachments": 0 }
→ { "ok": false, "issues": [{ "severity": "high",
    "code": "secret-external", "text": "…",
    "fix": { "field": "to", "value": "", "label": "Remove external recipients" } }] }

Controls

  • Feature flag ai.cicod.inmailCompose in Administration, with separate switches for summaries, drafting and the pre-send check.
  • Allowed recipient domains for Secret and Confidential mail are set per tenant. The default is @cicod.com only.
  • Drafts, fixes and every Send anyway are written to the InMail audit log (feature: CICOD-AI Compose).
  • Permission trimming: summaries only include messages in the user's own mailbox. Audience suggestions only list groups the sender may address.
