Task Brief & Suggested Reply

Opens every task with a five-line brief of the whole timeline: what was asked, what has been done, the attachments, the current blocker and what's needed from you. A Next best action chip does the obvious next step in one click. Above the remark box, Suggest reply drafts the next remark or citizen reply in a formal, citizen-friendly or brief tone. The officer inserts it, edits it and posts it.

Screen: ECMS → Tasks → Task detailComponent: <ai-task-brief>Endpoints: /ecms/task-brief · /ecms/suggest-reply

2. How it works

A summariser reads the timeline in order. Rules find the blocker and the ask. A writer model drafts replies from templates and similar resolved tasks.

Capture

Task header fields, every remark, status change and attachment name, plus OCR text of attached images and PDFs, are sent to /ecms/task-brief.

Protect

The gateway removes personal data (NIN, phone, email) and trims remarks the viewer cannot see. Secret-classified tasks stay on the sovereign model.

Summarise

An LLM writes exactly five lines: request, progress, attachments, activity and deadline. Rules pick out the blocker ("not in stock", "pending") and any ask that names the viewer.

Next action

The ask is mapped to an ECMS action (approve, reassign, nudge, close) and the status it leads to. It is shown as one chip and never runs on its own.

Draft reply

/ecms/suggest-reply retrieves similar closed tasks and the MDA's tone guide, then writes a remark in the chosen tone, using anything the officer has already typed.

Confirm & learn

The officer inserts, edits or discards the draft and rates the brief. Every decision is sent to /feedback and used to tune prompts and templates.

4. How to implement it in ECMS

Mount (Task detail page)

<link rel="stylesheet" href="/ai/components/task-brief.css">
<script src="/ai/shared/ai-gateway.js"></script>
<script src="/ai/components/task-brief.js"></script>

<ai-task-brief mode="brief" source="#task"
               viewer="{{user.fullName}}"></ai-task-brief>
…
<ai-task-brief mode="reply" source="#task"
               intent="#remark"></ai-task-brief>
<textarea id="remark"></textarea>

<script>
document.addEventListener('ai-reply-insert', e =>
  remarkBox.setValue(e.detail.text));
document.addEventListener('ai-task-action', e =>
  taskStore.runAction(e.detail));   // host owns the task
</script>

Build steps

  1. Expose the task timeline (remarks, status changes, attachments) as one ordered list for the gateway.
  2. Run OCR on image and PDF attachments when they are uploaded and store the text with the file.
  3. Add /ecms/task-brief: five-line prompt, blocker and ask rules, action mapping.
  4. Add /ecms/suggest-reply: retrieval of similar closed tasks, and a tone guide per MDA.
  5. Mount both placements on task detail and wire the two events to the task store.
  6. Pilot on IT Support and Complaints. Track "Useful" rate and how much officers edit drafts.

Controls

  • Feature flag ai.ecms.taskBrief in ECMS Settings, on/off per tenant. Suggested reply can be switched off on its own.
  • The next best action is never run automatically. Actions that need approval rights only appear for users who have them.
  • Every brief, draft and decision is written to the ECMS Audit Log (feature: CICOD-AI Task Brief).
  • The brief is built only from remarks and files the viewer is allowed to see. Drafts are labelled as CICOD-AI-assisted in the audit trail.
