Dashboard Insights

Turns the Workflow Dashboard's charts into plain-English findings. Each card and chart gets an ✦ Explain button, an Insights strip at the top flags stalled queues and other anomalies, and admins see a Data consistency warning when the dashboard disagrees with other ECMS screens. Clicking an insight highlights the queue it refers to.

Screen: ECMS → Dashboard → Workflow DashboardComponent: <ai-dashboard-insights>Endpoint: /ecms/dashboard/insights · /explain

2. How it works

The numbers come from rules and statistics over the same aggregates the charts use. The LLM only writes the sentences, and every figure in a sentence is checked against the source.

Capture

The dashboard's aggregates (status counts, per-workflow bars, top queues) plus the same counts from All Tasks and Resource Utilization go to /ecms/dashboard/insights.

Protect

Only counts and queue names leave the page, with no task text or personal data. The gateway applies the tenant's classification policy and keeps the call on the sovereign model.

Detect

Rules and a per-queue time-series model flag stalled queues (closure rate under 0.5%), work piling up in progress, 0-closure departments and sudden spikes. A reconciliation job compares each figure with its source screen.

Narrate

An LLM turns the detected facts into two or three sentences. A checker rejects any sentence whose numbers don't match the facts list.

Output

Alert cards linked to a queue, inline explanations with the facts behind them, and an admin-only list of consistency gaps with the screen each figure came from.

Confirm & learn

Users pin, edit or dismiss explanations, and admins mark gaps as known or open a reconciliation. Every decision goes to /feedback and tunes the alert thresholds.

4. How to implement it in ECMS

Mount (Workflow Dashboard)

<div id="wf-dashboard"
     data-ai-crosscheck='{"allTasksOpen":15395,
       "utilAvg":0,"utilAssigned":644}'>
  <ai-dashboard-insights source="#wf-dashboard"
      viewer-role="admin"></ai-dashboard-insights>

  <div data-ai-explain="status"
       data-ai-data='{"open":161,"closed":14}'>
    <h3>Task Status</h3>
    <span data-ai-explain-slot></span>
    …
    <div data-ai-explain-out></div>
  </div>
  <div data-queue="Order Fulfilment" data-open="11003"
       data-progress="1" data-closed="2">…</div>
</div>

<script>
document.addEventListener('ai-insight-focus', e =>
  dashboard.highlightQueue(e.detail.queue));
</script>

Build steps

  1. Expose the dashboard aggregates (status, per-workflow, top queues) as one JSON the page already has.
  2. Add data-ai-explain, data-ai-explain-slot and data-ai-explain-out to each card.
  3. Build the reconciliation job that compares each dashboard figure with All Tasks and Resource Utilization every hour.
  4. Train per-queue baselines on 90 days of daily open/close counts for spike and stall detection.
  5. Add the narrative step with a numeric checker, and run it read-only for 2 weeks with admins.
  6. Send high-severity anomalies to the Daily Brief and InMail once precision is above 80%.

Controls

  • Feature flag ai.ecms.dashboardInsights in ECMS Settings, on/off per tenant.
  • Alert thresholds (stall below 0.5% closure, in-progress above 3× closed) are set per tenant.
  • Every insight shown, pinned or dismissed is written to the ECMS Audit Log (feature: CICOD-AI Insights).
  • Insights only cover queues the viewer can already see. Consistency warnings require the admin role.
