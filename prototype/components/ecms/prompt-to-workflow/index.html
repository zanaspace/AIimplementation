Prompt-to-Workflow

Building a new workflow in ECMS usually requires manually clicking through multiple tabs to configure queues, status flows, forms, escalation timers, and approval rules. Prompt-to-Workflow automates all of this. Simply describe your business process in one sentence, and the CICOD-AI instantly generates a complete, editable workflow draft. It also checks for common mistakes—like missing escalation paths or assigning approvals to empty roles—before automatically filling out all the setup tabs for your review.

2. How it works

An LLM constrained to the ECMS workflow JSON schema writes the draft. A validator then checks it against the tenant's queues, roles and users.

Capture

The officer's description plus the tenant's queue, queue-type and role catalogue are sent to /ecms/workflow/draft.

Protect

The gateway removes any personal names or contact details from the prompt. Only role names and counts, not user details, are shared with the model.

Generate

The model must return JSON that matches the ECMS schema (queue, queue type, statuses, form fields, escalation, approval levels). Amounts like "₦200k" and times like "48h" are turned into thresholds and timers.

Lint

Graph checks flag stages with no escalation, approver roles with no active users (e.g. "Fleet Officer" has 0), missing end states and near-duplicates of the 290 existing workflows.

Fill the wizard

"Apply to wizard" fills Process, Form, Escalation and Approval. The officer edits any tab before clicking Create.

Confirm & learn

Accepted, edited, regenerated and discarded drafts are recorded via /feedback, along with how much the officer changed before Create.

4. How to implement it in ECMS

Mount (Create Workflow page)

<link rel="stylesheet" href="/ai/components/prompt-to-workflow.css">
<script src="/ai/shared/ai-gateway.js"></script>
<script src="/ai/components/prompt-to-workflow.js"></script>

<ai-workflow-builder></ai-workflow-builder>

<script>
document.addEventListener('ai-workflow-apply', e => {
  const d = e.detail.draft;   // the wizard store owns state
  wizard.process.set({ queue: d.queue, queueType: d.queueType,
                       statuses: d.statuses });
  wizard.form.setFields(d.fields);
  wizard.escalation.set(d.escalation);
  wizard.approval.set(d.approvals);
});
</script>

Build steps

  1. Publish the ECMS workflow model as a JSON schema (queue, queue type, statuses, fields, escalation, approvals).
  2. Expose /ecms/workflow/draft on the CICOD-AI Gateway with schema-constrained output and the tenant catalogue in the prompt.
  3. Write the lint rules: escalation coverage, active users per approver role, end states, duplicate detection.
  4. Add the component above the wizard and wire ai-workflow-apply to the wizard store.
  5. Seed with 20 real MDA processes (vehicle repair, leave, procurement) and measure edits before Create.

Controls

  • Feature flag ai.ecms.promptToWorkflow in ECMS Settings, on/off per tenant.
  • Blockers (e.g. an approver role with no users) must be resolved before Create is enabled.
  • Every generated and applied draft is written to the ECMS Audit Log (feature: CICOD-AI Workflow).
  • Only workflow administrators see the component; drafts can only use roles and departments in this tenant.
