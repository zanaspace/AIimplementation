2. How it works

Semantic matching picks the form, and an extractor fills fields from the sentence.

Capture

The sentence, the user's profile (name, department) and the catalogue of forms their role can raise (name, description, queue, fields) go to /forms/find.

Match

Embeddings of each form's name, description and field labels are compared with the sentence. The top 3 forms get a score and the words that matched.

Extract

An LLM extractor with the form's field schema pulls out destination, dates, amounts, banks and names.

Confirm & learn

The user picks the form. Every choice goes to /feedback to improve matching.

4. How to implement it in Workspace and webforms

Mount (Request page + webform)

<link rel="stylesheet" href="/ai/components/request-finder.css">
<script src="/ai/shared/ai-gateway.js"></script>
<script src="/ai/components/request-finder.js"></script>

<!-- Request Forms page, above the cards -->
<ai-request-finder catalog="#form-cards"
   user="Prince Ekpenyong" department="Administration">
</ai-request-finder>

<script>
document.addEventListener('ai-request-open', e =>
  webform.open(e.detail.form, { prefill: e.detail.fields }));
</script>

Build steps

  1. Expose the role-trimmed form catalogue with each form's description and field schema (labels, types, required).
  2. Embed the catalogue nightly and whenever a form is created or edited in ECMS → Forms.
  3. Expose /forms/find: embedding match, then LLM field extraction against the chosen form's schema.

API contract

POST /ai/forms/find
{ "query": "expense request to Kaduna next week…",
  "user": "Prince Ekpenyong", "department": "Administration",
  "forms": [{ "name": "EXPENSE REQUEST",
              "fields": ["Destination", "Departure date", "…"] }] }
→ { "model": "cicod-formfinder-v1",
    "matches": [{ "form": "EXPENSE REQUEST", "score": 0.95,
      "fields": { "Destination": "Kaduna",
                  "Amount requested (₦)": "₦185,000" } }] }

Controls

  • Feature flag ai.cicod.requestFinder in Administration.
  • Every match and field used is written to the audit log (feature: Request Finder).
  • Permission trimming: the catalogue sent to the model only holds forms the user's role can raise.
