Predictive Maintenance Auto-Scheduler

Reads each asset's repair history in ECMS and its usage (run-hours, kilometres, days in service) and predicts which assets are likely to fail before they're serviced. For each one it explains why, compares the cost of servicing now with the cost of a breakdown, and drafts a preventive repair task for the right ECMS queue. A store officer confirms every task.

Screen: Assets → Manage Asset → Maintenance (new tab)Component: <ai-maintenance-scheduler>Endpoint: /ims/maintenance/forecast

2. How it works

A survival model does the prediction and an LLM only writes the explanation and the task text, so the numbers are reproducible and can be audited.

Collect history

Repair tasks are matched to an asset by its code and by text such as "generator", "brake" or "FG 214 KJA" in ECMS queues (AUTO MOBILE REPAIR, IT Support, Facility). Usage comes from IMS meter readings, trip logs and issue dates.

Protect

Only asset codes and repair metadata go to the gateway. Nothing about individual staff is sent. Everything runs on the sovereign model.

Model failure

A Weibull survival model is fitted per asset category, giving a shape and a scale. Where there's enough history, it's adjusted per asset. The model gives the chance of failing in the next N days, given the usage since the last service.

Pick the service date

The "service by" date is when the chance of failure passes 20%. The "likely failure" date is when it passes 50%. Expected avoidable cost is (breakdown cost − preventive cost) × chance of failure.

Draft the task

An LLM writes the reason and a task description from the model's output. The queue, type and assignee come from the category's repair routing and the Resources shifts.

Confirm & learn

The officer creates, edits or dismisses the task. When the repair task closes, its outcome (whether a fault was found) is fed back, and the model is refitted every month.

3. Benefits to this feature

These are targets, based on typical results from preventive maintenance programmes. The baseline is measured from ECMS repair tasks before the pilot.

−40%

Unplanned breakdowns

Fewer emergency repair tasks raised after something has already failed, such as the generator shutdown in task #17391.

4–7×

Cheaper to act early

A preventive service costs a fraction of a breakdown. The generator example is ₦85,000 against ₦620,000, plus two days without power.

Less downtime

Assets available when needed

Vehicles, generators and AC units are serviced in a planned slot, not when the Director's office is already too hot to work in.

Budget

Plannable maintenance spend

The forecast list becomes next quarter's maintenance budget, with the expected avoidable cost as the justification.

Audit

A traceable reason for every job

Each preventive task records the prediction, the evidence and who approved it.

Mount (Manage Asset → Maintenance tab)

<link rel="stylesheet" href="/ai/components/ims-predictive-maintenance.css">
<script src="/ai/shared/ai-gateway.js"></script>
<script src="/ai/components/ims-predictive-maintenance.js"></script>

<ai-maintenance-scheduler assets="#asset-table"
                          horizon="30" high="0.5" medium="0.25">
</ai-maintenance-scheduler>

<script>
el.addEventListener('ai-maintenance-schedule', async e => {
  // host creates the task through the existing ECMS API
  const id = await ecms.tasks.create(e.detail.task);
  ims.assets.setStatus(e.detail.code, 'Service scheduled', { taskId: id });
});
</script>

Build steps

  1. Add usage fields to maintainable assets in IMS: meter unit (hours, km or days), current reading and last service date. Add a "Maintainable" flag to the Asset Type setting.
  2. Link repair tasks to assets: add an optional assetCode field to repair queue forms, and backfill history by matching task text.
  3. Fit Weibull models per category from the linked history. Where a category has fewer than 5 failures, fall back to manufacturer service intervals.
  4. Build /ims/maintenance/forecast on the AI Gateway as a nightly batch plus on-demand requests.
  5. Add the Maintenance tab and the component. Wire task creation to the ECMS tasks API. Suggest creating a "Facility Management" queue if the tenant doesn't have one.
  6. Pilot with generators and vehicles. Compare unplanned repair tasks against the previous 6 months.

Controls

  • Feature flag ai.assets.predictiveMaintenance, set per tenant.
  • The High and Medium thresholds are set per tenant (defaults 50% and 25%). Categories can be excluded.
  • Suggestions only. Every task needs a click, and bulk creation asks for confirmation and lists every task first.
  • Each forecast, task and dismissal goes to the IMS Audit log (Settings → Audit) with the model version.
  • Officers only see assets in stores they manage. Tasks can only go to queues the officer may raise.
