Smart Dispatch & Workload Balancing

Shows how much open work each resource carries against the capacity of their shift, and proposes a Rebalance: move N tasks from one resource to another, with the reason (shared skill, shift, schedule or suspension). Each move is accepted on its own. A Shift validation card flags broken shifts in the tenant, such as "dame 9:30 AM – 4:45 AM", and suggests a fix.

2. How it works

An optimiser does the assignment, rules check the shifts, and the LLM only explains each move in plain English.

Capture

Resources (status, department, resource type and level as skills, shift, schedule) and their open task counts go to /ecms/resources/rebalance. Shifts go to /validate-shifts.

Protect

Only names, counts and schedule data are sent; emails and phones are removed by the gateway. Processing stays on the sovereign deployment.

Optimise

Capacity is shift hours × open tasks per hour. A greedy assignment moves work off suspended and over-capacity resources to the least-loaded resource with a shared skill who is on shift, aiming at 85% utilisation.

Validate

Rules catch shifts that end before they start, very short early-morning shifts, midnight starts used on day schedules, and shifts over 10 hours. The LLM proposes the most likely intended times.

Output

Workload bars against capacity, a list of moves with reasons and confidence, tasks that could not be placed, and shift issues with a suggested fix.

Confirm & learn

The manager accepts or skips each move and fix. Decisions go to /feedback; skipped moves teach the optimiser which skill matches are wrong.

4. How to implement it in ECMS

Mount (All Resources page)

<link rel="stylesheet" href="/ai/components/smart-dispatch.css">
<script src="/ai/shared/ai-gateway.js"></script>
<script src="/ai/components/smart-dispatch.js"></script>

<ai-smart-dispatch source="#resource-table"
    shifts="#shift-table" target-util="0.85"></ai-smart-dispatch>
<tr data-resource="ea" data-name="Dorcas"
    data-status="active" data-open="96"
    data-shift="Daily Shift"
    data-skills="IT Support|Application issue">…</tr>

<script>
document.addEventListener('ai-dispatch-move', e =>
  tasks.reassign(e.detail.from, e.detail.to,
                 e.detail.count, e.detail.skill));
</script>

Build steps

  1. Expose open task counts per resource and each resource's skills (resource type, level, workgroups).
  2. Add a bulk reassign API that moves the oldest N open tasks matching a skill from one resource to another.
  3. Build /ecms/resources/rebalance (optimiser + explanation) and /validate-shifts (rules + suggestion).
  4. Validate on save in Resource Shift so new broken shifts cannot be created.
  5. Pilot with the IT Support and Complaints workgroups; tune the tasks-per-hour setting from real closure rates.

Controls

  • Feature flag ai.ecms.smartDispatch in ECMS Settings, on/off per tenant.
  • Target utilisation (default 85%) and open tasks per shift hour (default 6) are set per tenant.
  • Every accepted move and shift fix is written to the ECMS Audit Log (feature: CICOD-AI Dispatch) with the tasks moved.
  • Moves only suggest resources in workgroups the manager can assign to; suspended resources are never targets.
