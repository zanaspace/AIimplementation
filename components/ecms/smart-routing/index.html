Smart Intake & Routing

Reads each new request as it's typed, or as it arrives by email or the portal. It suggests the Queue, Queue Type, Priority and Assignee and explains why. It also warns when the request looks like a duplicate. The officer confirms every suggestion.

2. How it works

A trained classifier handles the routing labels, an LLM covers new queues and writes the explanation, and a load-aware picker chooses the assignee.

Capture

Title, description, contact, attachment names and the channel (form, email, portal) are sent to /ecms/route-task.

Protect

The gateway removes personal data (NIN, phone, email) and applies the tenant's classification policy. Secret content stays on the sovereign model.

Classify

A classifier trained on the tenant's roughly 16k historical tasks predicts queue, queue type and priority. New or rare queues fall back to an LLM with the queue catalogue in the prompt.

Assign

Candidates come from the workgroup and resource type. They're scored on shift and schedule, skills level and current open load, taken from ECMS Resources.

Check

Embedding similarity against the last 90 days of tasks finds duplicates and similar resolved cases.

Confirm & learn

The officer uses, edits or rejects each field. Every decision is recorded via /feedback and used to retrain the model each week.

4. How to implement it in ECMS

Mount (Create Task page)

<link rel="stylesheet" href="/ai/components/smart-routing.css">
<script src="/ai/shared/ai-gateway.js"></script>
<script src="/ai/components/smart-routing.js"></script>

<ai-smart-routing source="#task-form"
                  auto-threshold="0.9"></ai-smart-routing>

<script>
document.addEventListener('ai-route-apply', e => {
  // host page owns the form state
  taskForm.setField(e.detail.field, e.detail.value);
});
</script>

Build steps

  1. Export historical tasks (title, description, queue, queue type, priority, assignee, status timings) as training data.
  2. Train a text classifier per tenant; hold out 20% to measure accuracy per queue.
  3. Expose /ecms/route-task on the CICOD-AI Gateway: classifier, then LLM fallback and explanation, then assignee scoring.
  4. Add the component to Create Task. Wire ai-route-apply to the form store.
  5. Run in suggestion mode for 4 weeks and track acceptance per queue.
  6. Turn on auto-routing per queue where acceptance is 90% or higher. Low-confidence items go to the Triage inbox.

Controls

  • Feature flag ai.ecms.smartRouting in ECMS Settings, on/off per tenant.
  • Auto-routing threshold is set per queue. It defaults to off, so the officer always confirms.
  • Every suggestion and decision is written to the ECMS Audit Log (feature: CICOD-AI Routing).
  • Assignee suggestions only include users the requester's role is allowed to assign to.
