CICOD-AI Form Builder

Most MDA forms still exist on paper. The officer either describes the form in a sentence or uploads a photo or PDF of the paper form. The CICOD-AI returns a field list with labels, types, required flags, validation and options, and a live preview. It also suggests Nigerian validation rules (phone format, NIN 11 digits, NUBAN 10 digits). Every field can be edited before "Use these fields".

Screen: ECMS → Forms → Create FormComponent: <ai-form-builder>Endpoint: /ecms/form/draft · /from-scan

2. How it works

Document intelligence reads the paper form's layout. An LLM turns labels and boxes, or a description, into typed fields, and a rules library adds Nigerian validation.

Capture

Either the description text goes to /ecms/form/draft, or the uploaded photo/PDF goes to /ecms/form/from-scan.

Protect

Scans are processed on the in-country document model. A filled-in form's handwritten values are discarded; only printed labels are kept, so no citizen data is stored.

Read the form

OCR plus layout analysis finds labels, blank lines, boxes and tick-boxes, with a confidence per line. Low-confidence lines are highlighted for checking.

Design fields

The LLM chooses a type for each label (Date, Currency, Dropdown, Signature…), marks required fields and suggests options, e.g. 36 states + FCT, GL 01–17.

Validate

A rules library proposes Nigerian formats: phone numbers (11 digits or +234), NIN and BVN (11 digits), NUBAN (10 digits), vehicle plates, and date order.

Confirm & learn

The officer edits, adds or removes rows, then clicks "Use these fields". Accepted suggestions and edits go to /feedback.

3. Benefits to this feature

Targets from the CICOD-AI augmentation analysis and newFeatures.md ("current form builder to optimise with CICOD-AI").

1 hr → 5 min

Time to build a form

Target: a 15-field form from a scan in minutes, instead of adding fields one by one.

Paper → digital

Digitising at scale

Registries can photograph existing paper forms and have them online the same day.

Bad data ↓

Validation by default

NIN, phone and account numbers are checked at entry, not corrected later by staff.

Same field types everywhere

"State of origin" and "Grade level" use the same dropdowns on every form, which makes reports comparable.

4. How to implement it in ECMS

Mount (Create Form page)

<link rel="stylesheet" href="/ai/components/prompt-to-form.css">
<script src="/ai/shared/ai-gateway.js"></script>
<script src="/ai/components/prompt-to-form.js"></script>

<ai-form-builder max-description="1500"></ai-form-builder>

<script>
document.addEventListener('ai-form-apply', e => {
  const d = e.detail;           // host owns the form draft
  formDraft.set({ name: d.name, type: d.formType,
                  description: d.description });
  formDraft.setFields(d.fields);
});
</script>

Build steps

  1. Map the ECMS form field types to a JSON schema (label, type, required, validation, options).
  2. Build the validation rules library (phone, NIN, BVN, NUBAN, plates, date order) and shared option lists (states, LGAs, grade levels).
  3. Expose /ecms/form/draft and /ecms/form/from-scan (document intelligence, then LLM) on the CICOD-AI Gateway.
  4. Mount the component on Create Form and wire ai-form-apply to the form draft.
  5. Pilot with 20 paper forms from Registry; measure fields kept unchanged.

Controls

  • Feature flag ai.ecms.promptToForm in ECMS Settings, on/off per tenant.
  • OCR lines below 85% confidence are highlighted and must be reviewed.
  • Generated and applied forms are written to the ECMS Audit Log (feature: CICOD-AI Forms).
  • Only users with form-creation permission see the component; scans inherit the uploader's Drive permissions.
