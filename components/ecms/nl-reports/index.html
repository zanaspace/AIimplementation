The CICOD-AI shows what it understood as editable filter chips, then draws a chart and a table and writes a one-paragraph summary. The report can be exported, saved or scheduled weekly.

2. How it works

The model writes a structured query against an allow-listed reporting schema, never raw SQL. The chips are that query, so the user can see and correct exactly what will run.

Capture

The prompt and any chip edits are sent to /ecms/reports/nl-query with the user's role, so the query can be permission-trimmed.

Protect

The gateway redacts personal data in the prompt and applies classification routing. Only the schema and prompt go to the sovereign model; task rows never leave ECMS.

Text to query

An LLM maps the prompt onto a fixed query shape: measure, group-by, period, filters and limit. A validator rejects unknown fields and caps row counts.

Run & chart

ECMS runs the query on its own reporting store with the user's permissions. The component picks a bar chart and table, and the LLM writes a short summary from the result rows only.

Output

Editable chips, chart, table, narrative, and Export CSV, Save report and Schedule weekly actions.

Confirm & learn

Chip edits, saves, exports and "Not what I meant" all go to /feedback. Chip corrections become training pairs for the text-to-query model.

4. How to implement it in ECMS

Mount (Reports page)

<link rel="stylesheet" href="/ai/components/nl-reports.css">
<script src="/ai/shared/ai-gateway.js"></script>
<script src="/ai/components/nl-reports.js"></script>

<ai-report-builder examples="Turnaround time by
  department for Q3|Top 5 assignees by closed
  tasks"></ai-report-builder>

<script>
document.addEventListener('ai-report-save', e =>
  reports.save(e.detail.title, e.detail.query));
document.addEventListener('ai-report-schedule', e =>
  reports.schedule(e.detail.query, 'weekly'));
</script>

Build steps

  1. Define the reporting schema: measures (count, open, closed, turnaround), dimensions (department, queue, queue type, assignee, priority) and periods.
  2. Expose a query endpoint in ECMS that accepts that shape and applies the user's permissions.
  3. Add /ecms/reports/nl-query to the CICOD-AI Gateway: prompt to query, validate, run, then summarise.
  4. Mount the component above the Set Filters state and wire save and schedule to the existing report store.
  5. Collect 200 real prompts from pilot users and tune until 85% run without chip edits.

API contract

POST /ai/ecms/reports/nl-query
{
  "prompt": "Open complaints by queue type this month",
  "overrides": { "period": "Q3 2026" }   // chip edits
}
→ 200

  "narrative": "Delivery leads with 214 tasks…"
}

Controls

  • Feature flag ai.ecms.nlReports in ECMS Settings, on/off per tenant.
  • Only allow-listed measures and dimensions can be queried; results are capped at 5,000 rows.
  • Every prompt, interpreted query and export is written to the ECMS Audit Log (feature: CICOD-AI Reports).
  • Queries run with the requesting user's permissions, so users only see departments and queues they already have access to.
