Audit Copilot

Lets auditors ask the ECMS Audit Log questions in plain English, such as "Who approved task 16363?". Each answer cites the log rows it is based on, and those rows are highlighted. An anomaly panel flags patterns a person would miss when scrolling: the same user approving task 16363 twice, approvals outside working hours, and a new IP address for a super admin.

2. How it works

Questions are turned into a filter over the log, not answered from memory, so every sentence points to real rows. Anomalies come from rules plus a per-user behaviour baseline.

Capture

The question and the log entries in scope (date range, filters) are sent to /ecms/audit/ask. The anomaly scan sends new entries to /ecms/audit/anomalies.

Protect

Emails in descriptions are masked and IP addresses are replaced with pseudonymous IDs before any model sees them. Audit data is classified Restricted, so it stays on the sovereign model.

Query & detect

An LLM maps the question to a structured filter (task ID, user, action, time window, IP) that runs on the log. Rules catch repeat approvals and off-hours actions; a 30-day baseline per user catches new IPs and unusual volumes.

Answer

The LLM writes a short answer from the matching rows only, and returns the row IDs it used. If nothing matches, it says so instead of guessing.

Output

An answer with cited rows highlighted and the interpreted filter shown; an anomaly list with severity, reason and the rows behind it.

Confirm & learn

Auditors mark answers helpful or not, and mark anomalies reviewed or open an investigation. Every decision goes to /feedback and lowers the score of patterns that are repeatedly dismissed.

4. How to implement it in ECMS

Mount (Audit Log page)

<link rel="stylesheet" href="/ai/components/audit-copilot.css">
<script src="/ai/shared/ai-gateway.js"></script>
<script src="/ai/components/audit-copilot.js"></script>

<ai-audit-copilot source="#audit-table"
                  work-hours="08:00-18:00"></ai-audit-copilot>
<table id="audit-table">
  <tr data-row="r3" data-time="26/09/2026 18:41"
      data-user="Praise" data-ip-id="ip-b"
      data-action="Approve Task with ID 16363" …>
</table>

<script>
document.addEventListener('ai-audit-cite', e =>
  auditTable.highlight(e.detail.rows));
</script>

Build steps

  1. Add full timestamps and a stable row ID to each audit entry in the table markup (the API already stores them).
  2. Build the IP pseudonymiser in the gateway and a 30-day per-user IP and hour baseline.
  3. Expose /ecms/audit/ask (question → filter → rows → answer) and /ecms/audit/anomalies.
  4. Block duplicate approvals at the API, and keep the anomaly rule to catch other paths.
  5. Connect "Open investigation" to a Complaints-style case queue for the security team.

API contract

POST /ai/ecms/audit/ask
{ "question": "Who approved task 16363?",
  "rows": [{ "row": "r3", "time": "26/09/2026 18:41",
     "user": "Praise", "ipId": "ip-b",
     "action": "Approve Task with ID 16363" }, …] }
→ 200
{ "model": "cicod-audit-qa-v1", "confidence": 0.9,
  "answer": "Task 16363 was approved 3 times…",
  "rows": ["r3", "r5", "r15"],
  "query": "description contains 16363 AND action = Approve" }

POST /ai/ecms/audit/anomalies
{ "rows": […], "workHours": "08:00-18:00" }
→ { "anomalies": [{ "id": "dup-Praise",
      "severity": "bad", "kind": "Repeat approval",
      "title": "Duplicate approval of 16363 …",
      "rows": ["r3", "r5", …] }] }

Controls

  • Feature flag ai.ecms.auditCopilot in ECMS Settings, on/off per tenant.
  • Working hours, off-hours severity and the IP baseline window (default 30 days) are set per tenant.
  • Every question, answer and anomaly decision is itself written to the Audit Log (feature: CICOD-AI Audit), so the copilot is auditable too.
  • Answers only use entries the asker can already see; a department admin cannot query other departments' logs.
