2. How it works

A sensitive-content classifier sets the level, pattern detectors find personal data, and a filing model learned from where similar files already sit proposes the folder and metadata.

Capture

The file name, size, type and extracted text (OCR for scans and images) are sent to /drive/classify-upload before the file is committed to a folder.

Protect

Every file is first scanned on the sovereign model. Anything that scores Secret or Top Secret, or carries a "RESTRICTED" marking, never leaves it. Only a redacted text sample reaches any general model.

Classify

A classifier trained on files whose level was set by records officers predicts the level. It combines content signals (budget figures, security terms, markings) with the level of the most similar files in Drive.

Detect personal data

Validated patterns find NINs and BVNs (11 digits, checksum and prefix rules) and Nigerian phone numbers. It reports counts and locations and shows masked examples only.

File

The folder, document type, tags and retention period are predicted from the tenant's folder tree and the retention schedule. The owning department comes from the letterhead and signatory.

Confirm & learn

The officer accepts or edits each value. Edits and downgrades are recorded via /feedback and in the Drive Audit Log, and they retrain the classifier every month.

4. How to implement it in Drive

Mount (Upload File(s) dialog)

<link rel="stylesheet" href="/ai/components/drive-smart-upload.css">
<script src="/ai/shared/ai-gateway.js"></script>
<script src="/ai/components/drive-smart-upload.js"></script>

<ai-smart-upload owner="Prince Ekpenyong"
                 sovereign-levels="Secret,Top Secret"></ai-smart-upload>

<script>
document.addEventListener('ai-upload-accept', e => {
  // host page owns the upload and the folder tree
  drive.upload(file, {
    folder: e.detail.folder,
    classification: e.detail.classification,
    metadata: { type: e.detail.docType, tags: e.detail.tags,
                retention: e.detail.retention },
    redactedCopy: e.detail.redact
  });
});
</script>

Build steps

  1. Export existing files with their level, folder and owner as training data. Exclude files still at the default level with no review.
  2. Build the PII detectors (NIN, BVN, phone) with validation rules, and test them on a labelled sample of HR spreadsheets.
  3. Train the level classifier on the sovereign model; hold out 20% and measure accuracy per level.
  4. Expose /drive/classify-upload on the CICOD-AI Gateway: extract, detect PII, classify, then suggest filing.
  5. Add the component to the upload dialog. Wire ai-upload-accept to the upload call and the redacted-copy service.
  6. Run in suggestion mode for a quarter; add the same check to Edit Classification and Share File.

Controls

  • Feature flag ai.cicod.driveSmartUpload in Drive Preferences, on/off per tenant.
  • Thresholds: below 70% confidence the level field is left empty and the officer must choose. Levels in sovereign-levels are processed only on the sovereign model.
  • Every suggestion, edit and downgrade (with reason) is written to the Drive Audit Log (feature: CICOD-AI Classification).
  • Folder suggestions only include folders the uploader can write to. Examples of personal data are always masked in the dialog.
