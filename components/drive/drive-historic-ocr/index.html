Historic Files OCR & Search

Historic Files holds scanned file jackets that today can only be found by file name, and the live tenant shows "Open a folder to view files" with nothing searchable. CICOD-AI reads every scanned page with OCR. It shows an OCR status for each file, lets officers search by meaning inside the pages (with the matching page and highlighted text), and extracts the file reference, dates, parties, subject and signatures for the records officer to confirm.

2. How it works

A document-intelligence pipeline turns each scanned page into text and layout, a vector index makes it searchable by meaning, and an extractor fills in the records metadata.

Capture

Scanned PDFs and TIFFs in Historic Files are queued for OCR on upload or migration. Each page's text, layout and detected stamps and signatures are stored, and the status column shows Processing until done.

Protect

OCR and search run on the sovereign model inside the CICOD data centre. Personal data (NIN, phone) is masked in snippets, and Secret and Top Secret jackets are only indexed for users cleared for that level.

Read & index

An OCR model tuned for typed and handwritten CICOD enterprise files produces text with a confidence per word. Pages are split into passages and embedded; each passage keeps its page number.

Search

The query is parsed into topic, year and place. Hybrid search (keyword + vector) finds passages, a reranker orders them, and synonyms such as "allotment" for "allocation" are explained.

Extract

A layout-aware extractor reads the jacket's reference number, subject, dates, parties and signature blocks. Fields below 75% confidence, often handwriting, are marked "Needs review".

Confirm & learn

The records officer accepts, edits or rejects the metadata. Result clicks and "Not relevant" marks go to /feedback to tune the ranking; corrected fields retrain the extractor.

4. How to implement it in Drive

Mount (Historic Files page)

<link rel="stylesheet" href="/ai/components/drive-historic-ocr.css">
<script src="/ai/shared/ai-gateway.js"></script>
<script src="/ai/components/drive-historic-ocr.js"></script>

<ai-ocr-search folder="LANDS_FILE_JACKETS_2015-2020"
               min-confidence="0.75"></ai-ocr-search>

<script>
document.addEventListener('ai-ocr-status', e =>
  fileTable.setOcrStatus(e.detail.files));
document.addEventListener('ai-ocr-open', e =>
  viewer.open(e.detail.fileId, { page: e.detail.page }));
document.addEventListener('ai-ocr-metadata-apply', e =>
  driveApi.saveMetadata(e.detail.fileId, e.detail.metadata));
// row button: document.querySelector('ai-ocr-search').inspect(id)
</script>

Build steps

  1. Add an OCR job to the Drive upload pipeline for image PDFs and TIFFs; back-fill every file in Historic Files.
  2. Store page text, word confidence and signature/stamp boxes per page; expose status via /drive/ocr-status.
  3. Embed passages into the unified index with the file's ACL and classification, so results are permission-trimmed.
  4. Expose /drive/historic-search (query parsing, hybrid search, reranking) and /drive/ocr-extract on the CICOD-AI Gateway.
  5. Add the component and the OCR status column to Historic Files; add the metadata fields to the file record.
  6. Pilot on one registry (e.g. Lands) and measure top-3 success and the share of metadata accepted without edits.

Controls

  • Feature flag ai.cicod.driveHistoricOcr in Drive settings, on/off per tenant and per folder.
  • Review threshold min-confidence defaults to 0.75; below it the file shows "Needs review" and metadata is never saved without a person.
  • Every search, result click and metadata decision is written to the Drive Audit Log (feature: CICOD-AI Historic OCR).
  • Search results and snippets are trimmed to files the user can open; Secret jackets are processed on the sovereign model only.
