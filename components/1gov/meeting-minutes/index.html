CICOD-AI Minutes of Meeting

After a Conference meeting, the recording becomes minutes, decisions and action items in about a minute, with a transcript you can search ("where did we talk about the budget?"). One click saves the minutes to Drive → General Documents / MINUTES_OF_MEETINGS, a folder that already exists. Another click turns the action items into ECMS tasks, with assignees taken from the attendance list.

Screen: Conference → RecordingsComponent: <ai-meeting-minutes>Endpoint: /conference/minutes

    2. How it works

    Speech recognition with speaker labels, then an LLM that writes minutes in the formal executive format and pulls out decisions and actions, each linked to the moment it was said.

    Capture

    The recording audio, the room, the date and the attendance list (Conference → Attendance) go to /conference/minutes.

    Protect

    Audio is transcribed on the sovereign ASR service and never leaves the tenant's region. Rooms marked Confidential or Secret use the on-prem model only.

    Transcribe

    ASR tuned for Nigerian English produces timestamped segments. Diarisation matches voices to attendee names from their earlier meetings.

    Summarise

    The LLM writes a summary, agenda notes, decisions and action items (owner, due date, queue), each with the timestamp it came from, so it can be checked.

    Index

    Transcript segments are embedded for recording search, so "budget" also finds "412 million naira" and "capital release".

    Confirm & learn

    The host edits the minutes, unticks or reassigns actions, then saves to Drive and creates ECMS tasks. Edits and "Not accurate" go to /feedback.

    4. How to implement it in Conference

    Mount (Recordings page)

    <link rel="stylesheet" href="/ai/components/meeting-minutes.css">
<script src="/ai/shared/ai-gateway.js"></script>
<script src="/ai/components/meeting-minutes.js"></script>

<ai-meeting-minutes id="minutes"
   drive-path="General Documents/MINUTES_OF_MEETINGS"></ai-meeting-minutes>

<script>
function openMinutes(rec) {
  const m = document.getElementById('minutes');
  m.setAttribute('meeting-title', rec.title);  /* room, date, duration… */
  m.setAttribute('attendees', rec.attendance.join('|'));
  m.setAttribute('recording', rec.id);  // set last: loads
}
document.addEventListener('ai-minutes-save',  e => drive.save(e.detail));
document.addEventListener('ai-minutes-tasks', e => ecms.createTasks(e.detail.tasks));
document.addEventListener('ai-minutes-seek',  e => player.seek(e.detail.t));
</script>

    Build steps

    1. Fix the Recordings 500 error, and emit a "recording ready" event with the audio URL and attendance.
    2. Deploy sovereign ASR with diarisation. Tune it on 20 hours of tenant meetings (Nigerian English, local names).
    3. Expose /conference/minutes: ASR, then LLM with the minutes template, then extraction of actions and decisions with timestamps.
    4. Use Drive's upload API for MINUTES_OF_MEETINGS, and ECMS create-task with Smart Routing (E-T1) for the queue.
    5. Add /conference/search over embedded transcript segments for C5.

    Controls

    • Feature flag ai.cicod.meetingMinutes in Administration. Auto-generation is off by default and can be set per room.
    • Only actions at 70% confidence or more are pre-ticked. Nothing is saved or created without the host's click.
    • Saves, created tasks, edits and "Not accurate" are written to the Conference audit log (feature: CICOD-AI Minutes).
    • Permission trimming: only the host and attendees can open the minutes. The Drive file inherits the room's classification.
