Ask CICOD (search & commands)

One box in the top bar of every CICOD app. Staff type a question, a command or a "how do I…" in plain English. It answers with citations from Drive, ECMS, InMail and Assets, hides anything above the user's clearance (and says so), previews actions such as creating a task before anything happens, and answers help questions from the Help Centre and the CICOD Drive User Manual.

2. How it works

Retrieval-augmented generation over one unified index, plus tool calls into the app APIs. Actions always stop at a preview.

Capture

The query, the current app and the user's session go to /search/ask. An intent classifier picks search, command or help.

Protect

The gateway filters the index by the user's ACLs and clearance before retrieval, so the model never reads a Secret document for a Confidential user. It only returns a count of hidden hits.

Retrieve

Hybrid search (keywords + embeddings) over the unified index of Drive files, ECMS tasks and reports, InMail circulars and IMS assets. The Help Centre and CICOD Drive User Manual form a separate help index.

Answer or plan

The sovereign LLM writes a short answer with [n] citations to the results. For commands it fills a tool call (ECMS create-task, Conference schedule) and checks for duplicates.

Preview

Commands appear as an editable preview. Only Confirm calls the app API, with the user's own token.

Confirm & learn

Opened results, Helpful / Not helpful, Confirm, Cancel and escalations go to /feedback. They tune ranking and show which help articles are missing.

4. How to implement it across CICOD

Mount (shared app header)

<link rel="stylesheet" href="/ai/components/ask-cicod.css">
<script src="/ai/shared/ai-gateway.js"></script>
<script src="/ai/components/ask-cicod.js"></script>

<!-- in the top bar, left of the avatar -->
<ai-ask-cicod clearance="Confidential"
             user="Prince E."
             department="Administration"></ai-ask-cicod>

<script>
document.addEventListener('ai-ask-open', e =>
  router.open(e.detail.result.app, e.detail.result.id));
document.addEventListener('ai-ask-command', e =>
  actions.run(e.detail.intent, e.detail.fields));
document.addEventListener('ai-ask-escalate', e =>
  reportIssue.open(e.detail));
</script>

Build steps

  1. Build the unified index (section 2.2): Drive, ECMS, InMail and IMS push create/update events with ACLs and classification.
  2. Index the Help Centre, Start Tour content and the CICOD Drive User Manual as a separate help collection.
  3. Expose /search/ask: intent classifier, ACL-filtered hybrid retrieval, then LLM answer with citations.
  4. Register tools with strict schemas: ecms.createTask, conference.schedule. Every tool needs Confirm.
  5. Add the component to the shared header. Log zero-result queries to find index and help gaps.

Controls

  • Feature flag ai.cicod.askCicod in Administration, on/off per tenant. Commands can be switched off separately.
  • Answers need at least one citation with a retrieval score of 0.35 or more. Otherwise the user sees results only, with no generated answer.
  • Every query, result opened and confirmed action is written to the audit log (feature: Ask CICOD). Query text is kept for 30 days.
  • Permission trimming happens at retrieval time using the user's ACLs and clearance. Hidden results are counted, never named.
